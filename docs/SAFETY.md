# 使用前了解修改范围与风险

本文适用于 **Windows 1.3.0** 和 **macOS 0.1.0**。两个平台分别实现、分别编号，恢复能力也不同。

工具的改动集中在文件关联候选和应用注册信息。当前源码中未发现修改系统启动、驱动或服务配置的操作路径，但这不等于对所有电脑、系统版本和软件组合作出“零风险”的保证。最直接的影响是应用是否出现在“打开方式”中、近期文件记录和相关打开行为发生变化。

## 先区分扫描和清理

“扫描 / 预览”“扫描记录”和只读诊断用于读取信息、检查路径、生成待处理项目，**不会执行候选清理**。点击清理按钮并确认具体项目后，才会进行相应修改。

列表中出现某个应用，不一定说明它是残留；没有图标也不能单独证明应用已被彻底删除。先核对应用名称、完整路径、文件类型和判定原因，再决定是否处理。

## Windows：修改的是哪些注册表内容

清理主要处理 `OpenWithList`、`OpenWithProgids`、最近使用顺序 `MRUList`，以及用于隐藏候选的 `NoOpenWith` 标记。程序对允许写入的位置和类型设有白名单；只会删除确认仍为空的候选叶子键，不会正常计划删除整个应用或 ProgID 注册项。

代码禁止直接修改 `UserChoice` / `Hash` 和文件类型默认值，也不以“清理注册表”为由扫描并删除其他无关配置。当前版本未发现写入启动、驱动或服务区域的操作路径；不能据此断言任何意外都不可能发生。

使用时需要理解以下具体边界：

- **同名 EXE 会合并处理。** 识别依据包含完整 EXE 文件名，例如 `example.exe`，不以安装目录区分所有候选。不同版本，甚至两个无关但同名的程序，可能共用这些记录。选择某个安装目录并不保证只影响那一份程序，请查看预览中的来源与路径。
- **近期记录可能改变。** 清理使用历史和 `MRUList` 会改变“打开方式”的最近使用记录；新增 `NoOpenWith` 还可能使相关文件不再出现在该应用的任务栏跳转列表中。
- **系统范围会影响其他用户。** 默认只处理当前用户范围。勾选“同时清理系统注册项”并使用管理员权限后，会涉及 `HKLM` 中的关联记录，其他账户看到的候选也可能变化。通过另一个管理员账户提权时，当前用户注册表和备份目录会切换到该账户。
- **默认应用保护有覆盖边界。** 程序读取原始注册表关联记录，并对已识别仍为默认的目标阻止清理；它没有完整枚举 Windows 最终采用的所有动态、打包或其他有效默认关联。读取不完整时，只跳过新增隐藏标记，其他候选或历史项目仍可能处理。不能将“不直接写 UserChoice”理解为“所有默认打开行为在任何系统上都保证不受影响”。

### Windows 备份可以做什么

清理前会先把逐项备份保存到磁盘；备份失败则不执行清理。执行时核对扫描后数据是否变化，写入后再验证。备份通常位于：

```text
%LOCALAPPDATA%\OpenWithCleaner\Backups
```

**执行不是一次不可分割的事务。** 途中遇到权限、冲突、写入或日志错误时，会停止后续操作，但此前的项目可能已经修改，不会自动全部撤销。请查看“完成 / 跳过 / 失败”的结果和备份，再决定恢复或重新扫描。

恢复会核对计算机身份，当前用户范围还会核对 Windows 用户身份；只回退仍与本工具写后状态一致的项目。其他软件后来再次修改的值会保留，因此恢复可能跳过一部分项目。XML 保存的是本工具处理过的关联记录，**不是 Windows 系统镜像，也不保证在任何后续状态下都能一键恢复原状**。请保留本机生成的原始备份。

## macOS：精确注销失效路径的注册记录

Mac 版只允许对满足保守规则的本地 `.app` 路径执行定向注销：系统明确标记应用节点缺失，实际应用包也不存在，父目录和所在卷可确认，路径和标识没有歧义，且未检测到默认关联保护。仍存在的应用、系统项目、外接卷、符号链接及权限或状态无法确认的记录会保留。

清理不会删除应用文件，不改写其他应用的 `Info.plist`，不执行 Launch Services 全库重置，也不会在清理时自动重启 Finder。“重新注册应用…”和“重新启动 Finder…”是另外的用户操作。

Mac 版仍有以下限制：

- **默认保护不能覆盖所有处理程序。** 它只能保护系统可读取的显式选择和已识别的类型，不能保证发现所有动态关联。注销一条应用记录可能涉及该路径原有的文档类型及 URL 协议注册。
- **检查与执行不是原子操作。** 清理前会重新读取记录和检查路径，但最后一次检查与系统注销命令之间仍有短暂窗口。请避免在同一时间安装、更新、移动或重新注册目标应用。
- **失败提示不等于没有改动。** 系统命令可能已经执行，而后续读取或验证失败。遇到这种结果，应先重新扫描并查看操作记录，不能仅根据失败提示断定系统完全未变。
- **依赖系统工具的输出格式。** 扫描与定向注销使用 macOS 自带的 `lsregister`。它的文本输出不是 Apple 承诺稳定的公开解析接口，系统升级可能改变格式或行为。程序会保留不能确认的项目，但有限的兼容检查不能证明所有未来变化都能被预先识别。
- **候选可能再次出现。** 软件更新、重新安装或系统重新发现应用会产生新注册。工具没有永久隐藏名单，也不保证删除一次记录后它永远不再出现。

Mac 操作记录位于：

```text
~/Library/Application Support/OpenWithCleanerMac/Operations/
```

这些文件保存操作前后转储、所选项目和命令结果，便于核对发生了什么；**它们不能完整恢复 Launch Services 数据库**。已经删除的应用无法只凭文本记录恢复注册。重新安装后可重新注册实际存在的 `.app`，默认应用需要另行核对。

发布的 Mac 程序使用 **ad hoc 签名，未取得 Developer ID 签名或 Apple 公证**。完整性签名校验和 SHA-256 校验不等于 Apple 或独立机构完成了安全审计。首次运行可能受到 macOS 安全检查限制，具体操作见 [Mac 使用说明](../macos/README.md)。

## 已经验证了什么

- Windows 版通过 65 项测试：27 项清理引擎、7 项诊断、27 项程序可用性和 4 项界面过滤测试。测试使用内存注册表和临时文件，覆盖默认保护、冲突、备份失败和部分执行等场景；它们不等于在所有真实 Windows 环境中验证过每一种修改。
- Mac 版在 Intel 和 Apple Silicon 的 macOS 15 环境通过 56 项核心测试、3 项系统集成测试，并验证同一通用 ZIP 的签名、启动与扫描。真实清理测试创建唯一的临时应用，注册后删除，再注销其失效路径并核对结果。[查看构建与测试记录](https://github.com/575610871/open-with-cleaner-desktop/actions/runs/40119467763)。

这些是具体、有限的测试证据，**不是独立安全审计，也不是所有系统版本和第三方软件组合的安全认证**。Mac 的最低部署目标为 macOS 13，没有逐个实测所有支持范围内的系统版本。

## 使用建议与记录隐私

按需要逐个选择应用、查看预览后再清理。Windows 优先使用当前用户范围，非必要不以管理员模式处理系统项；保留原始备份。Mac 对标为“待确认”或“受保护”的记录，先核实来源，不要把它们当作必须清掉的垃圾。出现部分完成或验证失败时，先查看结果与记录，再决定下一步。

工具不会自动上传诊断、备份或操作记录。手动导出的报告可能包含程序路径、应用标识符；Windows 备份还包含用户和计算机身份信息。自行分享这些文件前，请检查其中的内容。
